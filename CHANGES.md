# Звіт про зміни

Що ми зробили зі стартовим AI-прототипом `triage`, щоб довести його до production-рівня.

## Результати

| прогін | бал |
|---|---|
| стартовий код, фейкова модель + chaos | 50.98 |
| перший прогін на справжньому Gemini | 84.32 |
| після короткого таймауту на спробу | 93.27 |
| фінальний, `--chaos`, повільний API | 83.57 |

Reliability 20/20 і 16 з 16 валідних відповідей у всіх прогонах зі збоями. Усі 35 офлайн-тестів проходять.

## Репозиторій

- Повернули оригінальний `.gitignore` (його перезаписав `*` від venv). Додали `.env.*` з винятком `!.env.example`, щоб ключ не потрапив у git.
- Віртуальне середовище перенесено з кореня проєкту в `.venv/`.

## `app/llm.py`: надійність викликів

- SDK-ретраї вимкнені (`max_retries=0`). Ретраї робимо самі під загальним дедлайном.
- Повторюємо 429, 5xx, таймаути та помилки з'єднання. Інші 4xx одразу вважаємо помилкою. Паузи між спробами зростають.
- Таймаут на спробу замість 600 с за замовчуванням: 2,5 с на першу, 8 с на другу, далі решта бюджету. Gemini відповідає то за ~1 с, то за 6–12 с, тому коротка перша спроба ловить швидкі відповіді.
- `content=None` і порожні `choices` обробляються як порожня відповідь. Відсутній ключ дає зрозумілу помилку замість `KeyError`.

## `app/triage.py`: коректність і безпека

- Порожні повідомлення, самі емодзі чи цифри обробляються без виклику моделі: `other / low / uk`.
- Довгий вхід обрізається до перших 1500 і останніх 400 символів.
- Промпт із правилами з README, англійською (дешевше за токенами). Окремо розмежовано повернення коштів (`payment`) і повернення товару (`returns`). Параметри `temperature=0`, `max_tokens=300`.
- Повідомлення клієнта передається в тегах `<msg>` як дані, а не інструкції.
- JSON витягується з markdown чи тексту навколо. Значення нормалізуються: `"false"` → `False`, `UA` → `uk`, зайві ключі відкидаються.
- Невалідна відповідь запускає до 3 спроб загалом.
- `urgent` завжди ставить `needs_human=True`.
- `summary` замінюється шаблоном, якщо вона не українською, довша за 200 символів або містить слово з injection.
- Загальний бюджет часу 16 с (ліміт harness — 20 с).
- Якщо модель так і не відповіла, працює fallback на ключових словах (категорія, пріоритет, мова). Виняток назовні не виходить.

## Тести

`tests/test_triage_strict.py` додає 26 тестів: зламані відповіді, ретраї, приведення типів, російська чи англійська `summary`, injection, дивні входи, величезний вхід, недоступний endpoint. Разом зі стартовими їх 35.

## Відомі обмеження

- Латентність API Gemini. У повільні періоди частина кейсів вичерпує бюджет і йде у fallback. Відповіді залишаються валідними, але падають точність і Efficiency.
- Можливе рішення, яке не реалізовано: паралельно запускати другий запит, якщо перший не відповів за ~2,5 с.
- Адаптивні таймаути перевірені на справжньому API лише в останньому `--chaos`-прогоні, коли API був повільним.
